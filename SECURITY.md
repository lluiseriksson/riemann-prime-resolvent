# Security and integrity

## Supported code

Security fixes target the current `main` branch and the latest tagged source release. Older research snapshots are retained for auditability but are not maintained as security-support branches.

## Private reports

Use GitHub's private vulnerability-reporting interface when it is available for this repository. Otherwise contact the repository owner through the GitHub profile and request a private channel before sharing details.

Report privately when an issue could enable dependency or workflow compromise, secret exposure, release/manifest bypass, artifact tampering, path traversal or unsafe archive extraction. Include the affected commit, a minimal reproduction and the expected impact. Do not open a public proof-of-concept before the maintainer has had a reasonable opportunity to assess it.

Mathematical errors, proof gaps and claim-boundary concerns should normally be public issues so the scholarly correction history remains auditable, unless they also expose a software-security vulnerability.
